# Agent Hub 日报与周报

把一份刊期作为一次完整交付。agent 复用 bot-workflow 和 newspaper 两个仓库的脚本，自己完成采集补查、模型写稿、编辑审核和验收。不要等用户逐项提醒外部资讯、锐评、榜单、网页或导览文案。脚本不代替事实审核，也不会自动补齐全部来源。

## 路径与环境

| 变量 | 含义 |
|---|---|
| `$NEWSPAPER` | newspaper 仓库根目录（Agent-Hub-Community/newspaper），命令默认在这里执行 |
| `$BOT` | bot-workflow 仓库根目录：`scripts/` 是写稿脚本，`prompts/` 是模型 prompt，`lib/llm.mjs` 读模型配置 |
| `$PIPELINE` | bot-workflow 仓库的 `pipeline/`，采集本机微信数据的脚本 |
| `$SKILL_DIR` | 本 skill 的目录 |
| `$WX_HOME` | wx CLI 使用的账号 HOME；脚本通过 `WX_ACTIVITY_HOME` 接收它 |
| `$BATCH` | 单日批次目录，默认 `$NEWSPAPER/scratch/day-D-runN` |
| `$EXTERNAL` | 本轮外部资讯目录，默认 `$NEWSPAPER/scratch/external-D-runN` |
| `$REPORTS` | 交付报告和导览草稿的目录，放在两个仓库之外 |
| `$SITE` | 站点地址，`https://agent-hub-community.github.io/newspaper/` |

`D` 是刊期日期，格式 `YYYY-MM-DD`。模型端点由 `DAILY_LLM_BASE_URL` 和 `DAILY_LLM_API_KEY` 指定，模型名由 `DAILY_LLM_MODEL` 指定（默认 `gemini-4-argon`）。其他环境变量见 bot-workflow 仓库的 `config/env.example`。命令里的变量都要换成本机实际值。

## 一句话入口

| 用户说法 | 执行到哪里 |
|---|---|
| “生成昨日完整日报” / “跑一下今天的日报” | 默认上一个完整的北京时间自然日。完成全部内容、榜单、本地网页验收和待发布的导览草稿，不发布。 |
| “生成并发布昨日完整日报，准备导览文案” | 同一次调用里完成审核、正式入库、反馈目录登记、提交推送、部署、线上核验和发布版导览文案，中途不再询问是否继续。 |
| “生成上周周报” / “来一下周报” | 上一个完整的北京时间自然周，按[周报流程](references/weekly.md)完成各群、资讯、该周榜单、资料库与黑话增量、本地网页和导览文案，不发布。 |
| “本周截至现在的周报” | 本周一到采集时刻的阶段稿，明确标为未完周，不当作完整自然周。 |
| “生成并发布上周周报” | 走周报流程。先核查周报发布链路，缺少时完成必要接入和测试，再连续发布和核验。不借用日报刊期或当前周榜冒充。真实受阻时交代已完成项和剩余项。 |
| “上线吧” | 沿用本会话已审核的刊期和批次，不因跨过午夜改成另一日期。检查稿件和授权后完成发布与交付，不重新采集或改稿。 |
| “继续” | 从该批次第一个未完成的阶段续跑，保留原有模式和授权，不扩大到发布或发群。 |
| “只改锐评 / 隐私 / 主题 / 链接” | 只改指定项，再做受影响的校验。不重跑整期，不重算榜单。 |
| “更新资料库” / “更新黑话词典” | 按[周报流程](references/weekly.md)第 8 节单独做一次增量：从上次收录截止日的次日起收集、审核、合并并本地验收，不发布。常规节奏是随周报每周一次。 |

显式日期优先。“今天的日报”表示今天执行上一个完整日的流程，开场说明内容日期。“今天截至现在的消息”按实时草稿处理，不能称为完整日，也不能跳过发布级的日终校验。范围含糊但能由当前批次确定时，自己确定；只有无法消除的刊期、目标或授权歧义才询问用户。

完整的新日报包含：`$NEWSPAPER/lib/groups.mjs` 中当天有读者版面的全部群（`pageGroups(D)`）、外部资讯、各版标题和重点、独立 AI 锐评、资料入口、各群日榜与社区周 / 月 / 总榜、网页和导览文案。`page: false` 或尚未到 `pageFrom` 的群照常采集并计入社区榜，但不出版面。历史刊期保留当时的群覆盖，不为当时还没有的群补造稿件或日榜。缺口要写明，不把未采集写成没有内容。新刊期的榜单与日终截止时刻一致；历史修订和界面修改不重算榜单，补报也不让当前社区榜回退。

本轮请求里的“发布”或“上线”是本轮刊期的发布授权，包括站点和反馈目录的必要更新，不包括发群、合并 PR、付费或更换平台。“全流程”本身不算外部写入授权，先完成预览和文案。导览文案默认只准备不发送。不建立无人值守的定时任务。

原始聊天、身份映射、模型响应和审核证据默认存于本地私有批次，不自动上传。指定范围的去凭据副本可另获明确授权后存入指定私有仓库；凭据、微信数据库和解密缓存不进入任何仓库。采集前的提权、客户端签名和账号初始化由运行者本人确认并执行，agent 不自动退出或重启微信。

## 一次调用的流程

先判定是 `daily` 还是 `weekly`。周报只执行[周报流程](references/weekly.md)，与日报共用编辑标准和授权边界；下面的日终打包、日榜刷新和发布器只用于日报。文件名含 week 的批量日报生成器不是周报生成器。

执行前读[操作手册](references/runbook.md)的相关阶段、[编辑标准](references/editorial-standards.md)，`$BOT/scripts/README.md`，以及 `$NEWSPAPER` 的 `docs/publishing.md` 和 `docs/external-news.md`。日报定稿还要读 `$BOT/docs/finalize.md`。具体参数、schema 和权限以两个仓库的当前实现为准。`$BOT/legacy/` 只供历史参考，不用于新刊期。

1. 固定刊期、北京时间窗口、执行模式和授权原话，定位两个仓库的工作树和已有批次。核验 wx CLI 账号：`HOME="$WX_HOME" wx sessions` 能看到目标群。把模型密钥临时导出为 `DAILY_LLM_API_KEY`，先用最小请求确认 `$BOT/lib/llm.mjs` 指定的模型正常响应；不改配置，不打印密钥。在批次目录记录阶段和证据，续跑时不覆盖已审核的稿件。
2. 主 agent 串行读取全部群的整日记录，再串行完成同一账号的榜单采集。外部资讯可以同时开始。各群写稿和互不重叠的外部稿可以并行；同一账号的数据库查询、同一文件的写入和预览构建不能并发。
3. 模型产出各群正文、标题、重点和独立锐评。主 agent 回查原话、发言归属、回复关系和分享原文；先选出有信息的条目再定条数，合并重复曝光，做隐私审查。
4. 外部资讯按[资讯补查](references/external-sources.md)扫描各类来源，记录覆盖情况和淘汰理由，再交模型并行写稿。来源发现可以交给独立的 subagent；阅读原文和事实审核不因委派而免除。
5. 按同一日终截止时刻计算日 / 周 / 月 / 总榜，逐张查看新增头像。主 agent 亲自逐条审核并补全重点标注，规则见[编辑标准](references/editorial-standards.md)。同步正文稿与重点映射，保留编辑来源，再刷新正文 revision、锐评、资料映射和审核凭证。
6. 主 agent 独占执行 `scripts/prepare-preview.mjs` 整合预览（见操作手册第 5 节），核对各版正文和全部榜单，完成真实路径和多视口验收，包括新版面的深链和历史缺稿回退。用常规主题，不延续已过期的节日主题。用模型准备一条合并导览草稿，不拆成分群消息。
7. 预览模式到此交付。已授权发布时按操作手册继续正式入库、公开构建、测试、反馈目录登记、提交推送、等待该提交的部署完成和线上核验。不要在第 6 步停下来重复请求授权。
8. 发布后只用核验器回读的线上数据（`data.js` 索引加当期 `issues/D.js`），以 `$BOT/scripts/generate-bot.mjs` 生成“已上线”导览文案（见操作手册第 7 节），复核其中的链接和事实，更新日报和资讯报告的发布状态。交付可点击的网页、榜单和文案，并写明未发群。

## 资料库、机会、黑话词典与搜索

资料库（`/library/`）、群聊黑话（`/glossary/`）和全站搜索（`/search/`）随构建生成。数据分别在 `data/library.json`、`data/glossary.json`，机会（群里发过的招聘、活动和征稿）在 `data/opportunities.json`。审核规范见 `$NEWSPAPER` 的 `docs/review/library.md`、`docs/review/glossary.md`、`docs/review/opportunities.md`。这些都是读者内容，发布需要授权。给 agent 的 Markdown、JSON 和 skill 与成员解耦，不含头像、发言者和讨论原话。

资料库、机会和黑话每周随周报补齐一次，见[周报流程](references/weekly.md)第 8 节。周报预览包含这次增量的预览，“发布周报”的授权同时覆盖这一周的增量。日报不更新它们；日报发布后只用一句话报出落后天数（今天减去 `data/library.json`、`data/glossary.json` 的 `through`），不追问。

站内语义检索依赖 `data/semantic-vectors.json`。日报、周报或资料库每次正式发布，都在公开构建之后、提交之前运行 `node scripts/embed-catalog.mjs`，把更新后的 `data/semantic-vectors.json` 一起提交。漏跑不会报错，公开构建会提示缺多少条。

## 授权与完成条件

主 agent 对整期完整性负责。subagent 完成或一次构建成功都不等于整期完成。每个阶段的完成都要有对应的文件和校验结果，见[操作手册的续跑与完成记录](references/runbook.md#8-续跑与完成记录)。

同一失败最多沿原路径重试一次，再换一种合理的替代方法。已有模块内部的重试也计入，不在外层叠加无限循环。以下情况保留成功的产物，并阻止受影响的稿件发布：模型不可用、原始数据缺页、隐私或事实争议未解决、头像未审、内容和榜单不一致。可以删除不实或无法支持的条目后重审，不能凑数绕过门禁。单个资讯平台失败时，记录缺口，用其他合格来源完成，不称全覆盖。

只有到达本轮模式的终点才结束。没有发布授权时，本地完整交付就是终点。已授权发布但部署或核验失败时，报告失败的准确阶段，不写“已上线且验收通过”。不得把历史的发布授权当作以后任意发布的许可。
