# 群聊采集、读图与活跃榜

本文说明 pipeline 怎样从本机的微信客户端读取群聊、图片和成员活跃度，以及运行者要做哪些准备。脚本的名称和参数见 [`pipeline/README.md`](../pipeline/README.md)。

## 前提

- 本流程只在 macOS 的微信 4.x 客户端上运行过。读图依赖这个客户端的附件目录格式。
- 需要一个已加入目标群、并在这台电脑上登录的微信账号。pipeline 只能读到这个账号在本机已经收到的消息：入群之前的历史、只在其他设备上的记录都读不到。
- 开始之前，在所在群说明用途并取得群成员知情，见 [README 的使用须知](../README.md#使用须知)。

## 1. 安装和初始化 wx CLI

[wx CLI](https://github.com/jackwener/wx-cli) 是第三方的开源工具（Apache-2.0 许可证），用命令行查询本机的微信数据。按它的 README：微信 4.x 用 SQLCipher 加密本地数据库；wx CLI 扫描运行中的微信进程的内存，取得数据库密钥，再按需解密并缓存。

下面的初始化由运行者本人决定并执行。本仓库的安装和 agent skill 不自动提权、重新签名、退出或重启微信，也不扫描或切换其他账号。

警告：先确认目标账号和客户端进程，再考虑初始化。重新签名会改动客户端；密钥提取会读取该进程的内存。多实例环境中，不应仅凭进程名猜账号。

1. 阅读所安装版本的 [wx CLI README](https://github.com/jackwener/wx-cli)，按其中的要求安装。需要重新签名或管理员权限时，由运行者本人确认；本仓库不提供自动修改微信客户端的安装脚本。
2. 给这个账号准备一个单独的 HOME 目录，下文记为 `$WX_HOME`。wx CLI 把配置、密钥和解密缓存放在 `$HOME/.wx-cli/`；单独的 HOME 让它与你日常的 wx 配置分开。之后的每条 wx 命令都带 `HOME="$WX_HOME"`；不带时，wx 读的是默认 HOME 下的另一份配置。
3. 在微信客户端里点开每个目标群，向上滚动加载一些消息。聊天库（`message_0.db`、`message_1.db` 等）的密钥只有在客户端访问过对应的聊天之后才留在内存里，刚启动、没打开过群的客户端会缺这些密钥。
4. 按 wx CLI 当前版本的说明，在目标账号的 `$WX_HOME` 下自行初始化。确认工具实际扫描目标进程，输出包含消息库密钥。只有已确认旧密钥失效时，才考虑该版本的重新扫描选项。初始化没有通用的多账号进程选择保证，不能把默认进程当作目标账号。
5. 验证能读到目标群：

   ```sh
   HOME="$WX_HOME" wx sessions --json -n 20
   HOME="$WX_HOME" wx history '<数字>@chatroom' --json -n 20
   ```

   `wx sessions` 输出里形如 `<数字>@chatroom` 的值就是群的 chatroom username，填进 `pipeline/groups.private.mjs`。

`$WX_HOME`、`.wx-cli/`、`all_keys.json` 和任何密钥都不提交到仓库，也不写进日志或报告。

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 报“找不到联系人” | 命令没带 `HOME="$WX_HOME"`，wx 读了另一份配置。 |
| 报 `file is not a database` | 解密缓存过期。先运行 `HOME="$WX_HOME" wx daemon stop`，清空 `$WX_HOME/.wx-cli/cache/`，再重试。 |
| 导出 0 条，或“最近”的消息停在旧日期，但客户端里有新消息 | 通常是消息库的密钥没取到。在客户端点开该群并滚动加载，再运行 `wx init --force`。 |
| `wx init` 报 `task_for_pid` 失败 | wx 找到的进程内存不可读：客户端没有按要求签名，或找错了进程。按 wx CLI 的 README 处理。 |

拿到完整数据之前，不要生成空的或只有半天的群稿。

## 2. 按日采集群聊

pipeline 对每个群、每一天单独采集：

- 时间窗口是北京时间 `D` 日 00:00 到次日 00:00，不含右端。当天还没结束时截到运行时刻，并把 `completeDay` 记为 `false`。
- 用 `wx history <chatroom> --since D --until D+1 -n 500 --offset K --json` 分页读取，直到某一页不足 500 条。两页内容完全相同时报错；读到 10000 条仍没读完时报错，不生成半截的输入。
- 多天的批次逐日串行采集，每天写进 `$BATCH/<日期>/`。同一账号的读取不并发。

每个群每天输出两个文件，目录权限 0700，文件权限 0600：

| 文件 | 内容 | 用途 |
|---|---|---|
| `group-N.raw.json` | wx 的原始输出，含群昵称 | 默认本地保存，用于核对和审稿 |
| `group-N.input.json` | 给模型的输入 | 写稿、榜单校验 |

`input.json` 里每条消息有编号（`m0001` 起）、时间、化名发言者（`p1`、`p2` 按当天首次发言排序，只在单群单日内有效）、类型和正文。正文去掉了密钥和令牌字段、手机号、邮箱、群 ID、微信 ID 和本机路径，未解析的 XML 媒体引用换成 `[媒体引用未解析]`。正文里群友互相称呼的昵称不会被替换。

`coverage` 字段记录状态（`local_records` 或 `no_local_records`）、是否整日、分页是否读尽、条数和首末时间。分页读尽只证明本次筛选读完了本地可查询的结果，不证明本机保存了微信的全部历史。`no_local_records` 只说明本机没有记录，不等于当天没人发言。

采集脚本不上传原始记录。另获明确授权后，可归档指定范围的去凭据副本到指定私有仓库；原始记录和身份不进入公开仓库，凭据、微信数据库和解密缓存不进入任何仓库。

## 3. 读图

读图在采集之后、写稿之前运行，为每条图片消息补上一段客观描述。

1. 定位：从解密后的消息库读出图片的文件哈希，到客户端的附件目录（账号数据目录下的 `msg/attach/`）找到对应的 `.dat` 文件。
2. 解码：客户端把图片存成 `.dat` 文件。V2 格式用由账号信息派生的密钥加密首块，V1 用固定密钥，更早的文件是单字节异或。脚本在运行时从客户端留在磁盘上的文件派生账号密钥，不写入，也不打印。
3. 判断质量：客户端显示过的图片才有原图，即有人在这台电脑上打开过该群并滚动经过它，或点开过它。其余只有收到时自动下载的缩略图，长边一两百像素；特别宽的原图，缩略图只保留中间一段。
4. 描述：多模态模型按本仓库的 `prompts/image-description.md` 写描述，内容是图的类型，以及讨论涉及的文字和数字。描述不写人名、昵称、账号、二维码、联系方式和网址；个人主页只写页面类型。脚本再替换掉漏网的链接、微信 ID 和 @账号。
5. 存放：解码后的图片放在 `$BATCH/<日期>/media/`。描述写进 `input.json` 对应消息的 `image` 字段，`content` 仍是 `[图片]`。写稿时生成器把它换成 `[图片（原图）：描述]` 或 `[图片（缩略图）：描述]`；原始讨论节选仍显示 `[图片]`。
6. 缓存：描述按图片 md5 缓存在 `scratch/image-descriptions/`。重跑只处理失败的图和新打开的图。重新采集会覆盖 `input.json`，之后要再读一次图。

缩略图上的小字和数字常被认错。审稿时只用缩略图描述判断图的大意，不把其中的数字当作已核实的事实。关键图片只有缩略图时，运行者可以在客户端里打开该群、滚动经过这些图片，然后重跑读图。

## 4. 活跃榜

活跃榜统计参与次数，不评价内容质量。榜单脚本和读图脚本以只读方式直接打开 wx CLI 的解密缓存（`$WX_HOME/.wx-cli/cache/`），所以先完成同一账号的群聊采集再运行它们。

- 成员 ID：微信 username 的 SHA-256 前 12 位（`activity.mjs` 的 `memberKey`），用于私有统计和证据关联，不进入公开榜单。
- 去重：按服务端消息 ID 跨数据库去重。
- 计数：文字、引用回复、图片、视频、语音、链接、文件和合并转发，每条计 1 次，媒体另列；系统消息、拍一拍和表情包不计。
- 窗口：日榜按群计算。社区周榜（北京时间自然周）、月榜（自然月）和总榜把所有已采集的群合在一起计算；总榜只覆盖本机留存的记录。
- 截止：刊期次日北京时间 00:00，不含该时刻。

公开快照只导出周榜、月榜、总榜的前三名，以及已发布日报对应的各群日榜。成员 ID 重新编号，不含姓名、微信 ID、分数和计分规则。头像从联系人头像地址下载到本机，逐张人工查看后才公开。微信返回“暂时无法查看”一类的占位图时视为缺失：保留名次，显示默认头像。完整统计、身份映射和私有审计留在本机的批次目录。

## 5. 资料库、机会与黑话的候选

- 资料库候选列出群里分享的链接，附带聊天上下文。设置了 `WX_ACTIVITY_HOME` 时，还记录分享者的成员哈希和联系人头像地址，不写微信 ID。候选文件含聊天上下文，默认留在 newspaper 仓库被忽略的 `scratch/` 下，不自动上传。
- 运营账号（发日报导览、向各群转发外部链接的账号）的成员哈希写在 `pipeline/groups.private.mjs` 的 `libraryOperators`。资料库把它的分享算作转发：不显示它的头像，只在没有群友分享同一链接时计入。
- 机会和黑话的候选从逐日的 `input.json` 生成，不另外读取微信数据。
- 审核和组装用 newspaper 仓库的脚本，规范见该仓库的 `docs/review/library.md`、`docs/review/opportunities.md` 和 `docs/review/glossary.md`。
